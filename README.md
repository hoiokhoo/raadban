# رصد‌بان — سامانه هوشمند رصد، راستی‌آزمایی و تحلیل تاریخ‌محور اخبار

سامانه‌ای برای گردآوری خودکار اخبار از منابع متنوع (تلگرام، ایتا، بله، RSS، وب)، استخراج ادعا، راستی‌آزمایی شفاف در سطح ادعا، حافظه تاریخی و تولید گزارش شبانه تاریخ‌دار برای هر دسته موضوعی.

> **اصل طراحی:** این سامانه «مولد متن» نیست. هر نتیجه تحلیلی با برچسب «تحلیل/محتمل» از خبر قطعی جدا می‌شود، نبود شواهد هرگز معادل نادرستی فرض نمی‌شود، و قابلیت‌های پیاده‌سازی‌نشده صریحاً «در انتظار پیاده‌سازی» اعلام می‌شوند — نه اتصال نمایشی.

---

## ۱. نصب و اجرا

### پیش‌نیازها
- Node.js 20+ یا Bun
- (در این محیط) پرژیم Next.js 16 + TypeScript + Prisma/SQLite از قبل آماده است

### مراحل نصب

```bash
# ۱) نصب وابستگی‌ها
bun install

# ۲) تنظیم متغیرهای محیطی (فایل .env)
DATABASE_URL=file:/home/z/my-project/db/custom.db
# SECRET_KEY=یک-راز-قوی-برای-رمزنگاری-کلیدهای-API   (در تولید حتماً تنظیم شود)

# ۳) ساخت پایگاه داده
bun run db:push

# ۴) Seed واقعی: دسته‌ها + پرامپت‌های تخصصی (خودرو عیناً از سند کاربر) + ۷ منبع واقعی آزمایش‌شده
bun run scripts/seed-real.ts

# ۵) اجرا
bun run dev        # حالا توسعه روی پورت 3000
bun run build && bun run start   # حالا تولید
```

### متغیرهای محیطی

| متغیر | توضیح |
|---|---|
| `DATABASE_URL` | مسیر فایل SQLite |
| `SECRET_KEY` | راز مشتق‌سازی کلید رمزنگاری AES-256-GCM برای کلیدهای API. **در تولید حتماً تنظیم کنید**؛ در نبود آن از پیش‌فرض توسعه استفاده می‌شود و پیام هشدار در همین مستند کافی است. |

## ۲. راهنمای اتصال API مدل هوش مصنوعی

1. به بخش **«مدل و API»** بروید.
2. نام مدل پیش‌فرض را وارد کنید (پیش‌فرض: `glm-4.5-air`).
3. در صورت استفاده از سرویس کلیددار، کلید را در فیلد «کلید API» وارد و ذخیره کنید:
   - کلید فقط سمت سرور با **AES-256-GCM** رمزنگاری و در پایگاه داده ذخیره می‌شود.
   - به مرورگر فقط نسخه ماسک‌شده (`sk-a••••xyz`) برمی‌گردد؛ در لاگ‌ها و خطاها ثبت نمی‌شود.
4. دکمه **«تست اتصال»** پیام خطای قابل فهم می‌دهد (احراز هویت ناموفق / محدودیت نرخ / سرویس در دسترس نیست).
5. **سقف مصرف روزانه** (توکن تقریبی) را تنظیم کنید؛ در عبور از سقف، فراخوانی‌های جدید با پیام صریح رد می‌شوند و هیچ داده ساختگی تولید نمی‌شود.
6. مصرف به تفکیک هدف (استخراج ادعا، راستی‌آزمایی، گزارش، کشف منبع، تحلیل) در بخش **«هزینه و مصرف»** ثبت و نمایش داده می‌شود.

> مدل هرگز بر دانش داخلی خود درباره «اخبار روز» حکم نمی‌دهد؛ راستی‌آزمایی فقط بر شواهد ارائه‌شده انجام می‌شود.
>
> **کنترل هم‌زمانی (فصل ۱۱):** همه فراخوانی‌های مدل از یک سدیمانت سراسری (حداکثر ۲ درخواست هم‌زمان) عبور می‌کنند؛ خطای محدودیت نرخ (429) با تأخیر افزایشی بلند (۸/۱۶ ثانیه) مدیریت می‌شود و مطلب ناموفق در وضعیت «خام» برای تلاش بعدی باقی می‌ماند — مراحل تکمیل‌شده دوباره اجرا نمی‌شوند.

## ۳. راهنمای افزودن منابع

### روش دستی (بخش «مدیریت منابع»)
- **افزودن تکی:** نام + پلتفرم + شناسه (نام کانال بدون `@` یا نشانی کامل). دسته‌ها، اولویت، زبان، منطقه، بازه دریافت (دقیقه)، سقف مطالب، یادداشت اعتماد.
- **افزودن گروهی:** در همان دیالوگ، هر سطر یک نشانی/شناسه؛ پلتفرم از نشانی حدس زده می‌شود.
- **وارد/صادر کردن:** فایل استاندارد JSON با قالب `khabar-rasi-export/v1` از همین بخش.
- قبل از ثبت، تکراری بودن (پلتفرم+شناسه) بررسی و رد می‌شود.

### کشف خودکار (بخش «کشف منابع با AI»)
موضوع را بنویسید؛ سامانه چند جست‌وجوی وب می‌زند، نامزدها را از **شواهد واقعی نتایج** استخراج و با معیارهای توضیح‌پذیر امتیاز می‌دهد (مرتبط‌بودن ۰-۴۰، تازگی ۰-۲۵، کیفیت پوشش ۰-۲۰، شواهد اعتبار ۰-۱۵).
- آمار اعضا/بازدید اگر در شواهد نباشد صریحاً **«نامعلوم»** ثبت می‌شود — هرگز ساختگی نیست.
- همه پیشنهادها با وضعیت **«در انتظار تأیید»** ثبت می‌شوند؛ فعال‌سازی خودکار فقط با کلید صریح شما.

### ورود دستی مطلب (بخش «جست‌وجو»)
وقتی دسترسی خودکار به منبعی ممکن نیست، می‌توانید متن را مستقیم وارد کنید: مطلب با برچسب صریح «ورود دستی» ثبت و وارد همان خط لوله (نرمال‌سازی، استخراج ادعا، راستی‌آزمایی) می‌شود. این قابلیت جایگزین اتصال‌دهنده نیست و هرگز به‌عنوان دریافت خودکار جلوه داده نمی‌شود.

### وضعیت‌های منبع
`دریافت_موفق` · `غیرفعال` · `خطای_اتصال` · `نیازمند_احراز` · `محدود_دسترسی` · `پشتیبانی‌نشده`

## ۴. راهنمای ساخت دسته و ویرایش پرامپت

1. در بخش **«دسته‌بندی‌ها»** دسته بسازید (نام + شناسه لاتین + رنگ + توضیح).
2. برای هر دسته می‌توانید **پرامپت اختصاصی تحلیل‌گر** بنویسید (تا ۱۲هزار نویسه): نقش هیئت کارشناسی، مأموریت روزانه، تفکیک موضوعات، روش راستی‌آزمایی، قواعد قطعی. این متن در تولید گزارش به سیستم‌پرامپت لایه می‌شود و نسخه آن در `PromptVersion` ثبت و در متادیتای گزارش (promptVersion) درج می‌گردد.
   - نمونه کامل آماده: پرامپت دسته **خودرو** (عیناً از سند کاربر، ~۷هزار نویسه) و چهار دسته اقتصاد/سیاست خارجی/فناوری/انرژی با همان سطح ساختار — همگی از `scripts/seed-real.ts`.
3. منابع را می‌توانید به چند دسته هم‌زمان متصل کنید؛ ادغام بازنشرها در سطح «رویداد یکتا» بین دسته‌ها مشترک است.

### خط لوله پردازش (قابل ردیابی برای هر مطلب)
دریافت خام → نرمال‌سازی/پاک‌سازی → تشخیص زبان → کیفیت (تبلیغ/ناقص) → استخراج تاریخ وقوع در برابر انتشار → تکراری‌یابی (هش + شباهت) → دسته‌بندی/اهمیت (AI) → رویداد یکتا → استخراج ادعا (AI) → راستی‌آزمایی (اختیاری جست‌وجوی وب) → گزارش شبانه → حافظه تاریخی.

مراحل انجام‌شده هر مطلب در `processingSteps` (JSON) ثبت می‌شود؛ شکست یک مرحله، مراحل قبلی را دوباره اجرا نمی‌کند.

### مدل داده (۱۴ موجودیت)
`Category` · `Source` · `SourceCategory` · `Post` · `PostCategory` · `Event` · `EventPost` · `Claim` · `Evidence` · `FactcheckReport` · `DailyReport` · `Prediction` · `SourceSuggestion` · `Setting` · `AiUsage` · `JobRun` · `PromptVersion`

## ۶. مستندات محدودیت هر پلتفرم

| پلتفرم | وضعیت | محدودیت‌های واقعی |
|---|---|---|
| تلگرام | ✅ پیاده‌سازی‌شده | فقط کانال‌های عمومی با پیش‌نمایش وب فعال (`t.me/s/...`). گروه‌ها/پیام خصوصی بدون Bot API و توکن دریافت نمی‌شود. سابقه محدود به صفحات پیش‌نمایش. در آزمون زنده این محیط: کانال تسنیم دریافت موفق؛ برخی کانال‌های دیگر پیش‌نمایش وب از این مسیر نمی‌دهند → خطای صادقانه. |
| ایتا | ✅ پیاده‌سازی‌شده | فقط کانال‌های عمومی دارای صفحه وب (`eitaa.com/{channel}`). پارسر با ساختار واقعی صفحه (`etme_widget_message`، `data-post`، `time datetime`) تطبیق داده شد؛ در آزمون زنده: ۱۱ پیام واقعی از کانال خبر. API عمومی مستند برای تاریخچه کامل ندارد؛ آمار اعضا نامعلوم. |
| بله | ✅ پیاده‌سازی‌شده | صفحه وب عمومی برای همه کانال‌ها فعال نیست؛ API عمومی مستند ندارد. در آزمون زنده این محیط صفحه عمومی کانال در دسترس نبود (404) → خطای صادقانه ثبت می‌شود، نه داده نمایشی. |
| RSS | ✅ پیاده‌سازی‌شده | پوشش دقیقاً تابع خوراک ارائه‌شده است. |
| وب‌سایت | ✅ پیاده‌سازی‌شده | استخراج HTML ایستا؛ صفحات SPA سنگین ممکن است خالی باشند. صیانه کیفیت: صفحاتی که فقط ناوبری/بازاریابی دارند (کمتر از ۶۰ کلمه طبیعی) با خطای صادقانه رد می‌شوند نه ثبت بی‌محتوا. برای پوشش پایدار RSS توصیه می‌شود. |
| توییتر/ایکس | ✅ پیاده‌سازی‌شده | از سرویس سندیکاسیون عمومی ایکس (`syndication.twitter.com`) بدون API پولی؛ فقط خط زمانی عمومی، ریپلای‌ها حذف، فقط توییت‌های خودِ حساب (نقل‌قول‌های حساب‌های دیگر پست مستقل حساب نمی‌شوند و RT با پرچم فوروارد ثبت می‌شود). ایکس از IP دیتاسنتر با ۴۲۹ محدودیت نرخ می‌گذارد — در آن حالت خطا صادقانه ثبت و در تیک بعدی تلاش می‌شود؛ از IP خانگی بدون تغییر کد کار می‌کند. |
| تروث سوشال | ✅ پیاده‌سازی‌شده | API عمومی وضعیت‌ها (`truthsocial.com/api/accounts/{handle}/statuses`)؛ Cloudflare از برخی IPهای دیتاسنتر جلگیری می‌کند (۴۰۳) → خطای صادقانه؛ مسیر جایگزین مجاز: بایگانی عمومی پست‌ها به‌صورت RSS (مثل trumpstruth.org برای ترامپ — با ذکر صریح «بایگانی عمومی» در نام منبع). |
| اینستاگرام | ⛔ در انتظار پیاده‌سازی | نیازمند Graph API و مجوز متا. |
| آپارات | ⛔ در انتظار پیاده‌سازی | — |

در رابط کاربری، بخش «خطاها و وضعیت سرویس‌ها» همین فهرست را با وضعیت واقعی نشان می‌دهد.

## ۷. ساختار پایگاه داده و پشتیبان‌گیری

- فایل پایگاه داده: `db/custom.db` (SQLite)
- **پشتیبان‌گیری:**
  ```bash
  sqlite3 db/custom.db ".backup 'backup-$(date +%F).db'"
  # یا ساده‌تر:
  cp db/custom.db backup-$(date +%F).db   # هنگام توقف سرویس
  ```
- **بازیابی:** سرویس را متوقف کنید، فایل پشتیبان را جایگزین کنید، `bun run db:push` برای اطمینان از هم‌نسخ بودن اسکیما، سپس اجرا.
- **نگهداشت:** سوابق `JobRun` و `AiUsage` موفق پس از ۳۰ روز خودکار پاک می‌شوند؛ گزارش‌ها، شواهد و ادعاها حذف نمی‌شوند (اصل بازبینی‌پذیری).
- نسخه‌های قبلی اطلاعات اصلاح‌شده حذف نمی‌شوند؛ ادعاها «منسوخ_یا_اصلاح‌شده» می‌شوند، نه بازنویسی بی‌تاریخ.

## ۸. زمان‌بندی و گزارش شبانه

تنظیم در بخش **«زمان‌بندی»** (یا `POST /api/schedule`):
- ساعت گزارش شبانه (پیش‌فرض `22:30`) — منطقه زمانی `Asia/Tehran`؛ بازه هر روز از نیمه‌شب تا نیمه‌شب بعدی تهران است.
- روزهای فعال هفته، جبران گزارش‌های ازدست‌رفته پس از قطعی (تا ۳ روز)، راستی‌آزمایی خودکار.
- زمان‌بند هر ۶۰ ثانیه یک tick اجرا می‌کند: دریافت منابع سررسید‌شده، پردازش مطالب خام، راستی‌آزمایی ادعاهای در انتظار (سقف هر tick)، تولید گزارش در ساعت تعیین‌شده.
- **قفل کارها** جلوی اجرای موازی تکراری را می‌گیرد؛ هر اجرا در `JobRun` ثبت می‌شود.
- گزارش ناقص (منابع خطادار یا بدون داده) با وضعیت «ناقص» و هشدار صریح منتشر می‌شود، هرگز به‌عنوان کامل.

## ۹. تست‌ها و نتایج واقعی

```bash
bun test    # هر ۵۲ تست
```

| مجموعه | تعداد | نتیجه واقعی آخرین اجرا |
|---|---|---|
| تست‌های واحد منطق هسته (`tests/core.test.ts`) | ۳۶ | ✅ ۳۶ پاس — ۰ شکست |
| تست‌های یکپارچه API (`tests/integration.test.ts`) | ۱۶ | ✅ ۱۶ پاس — ۰ شکست (۹۳ expect) |

تست‌های یکپارچه خودکفا هستند: آزمون تکراری‌بودن منبع ابتدا خودش منبع می‌سازد و آزمون جست‌وجو از ورودی دستی مطلب استفاده می‌کند — هیچ وابستگی به داده ساختگی Seed.

پوشش سناریوهای فصل ۱۴: افزودن/ویرایش/حذف منبع، رد منبع تکراری، ورودی نامعتبر، حفاظت ماسک کلید API، جلوگیری از گزارش تکراری (همان reportId)، رد تاریخ نامعتبر، مسدودسازی SSRF در جریان واقعی دریافت، ساعتی نامعتبر در زمان‌بندی، سوابق وظایف، جست‌وجو، پلتفرم‌های پشتیبانی‌نشده، نرمال‌سازی فارسی، تقویم جلالی (۳ کیس مرجع)، استخراج تاریخ از متن، تشخیص تبلیغ، تشخیص بازنشر با شباهت، رمزنگاری و دستکاری ciphertext، مسدودسازی localhost/priv-IP، محصورسازی تزریق، استخراج JSON امن، استخراج نام کانال از ۴ قالب.

**صحت‌سنجی زنده (۳۰ اکتبر ۲۰۲۶):**
- دریافت واقعی از ۷ منبع: RSS مهر، خبرآنلاین، دنیای اقتصاد، مشرق، اقتصادآنلاین (همگی «دریافت_موفق»، ~۱۵۰ مطلب) + تلگرام تسنیم (۲ پیام متنی؛ اکثر پست‌های کانال رسانه‌ای‌اند و طبق محدودیت ثبت‌شده دریافت نمی‌شوند) + ایتا «khabar» (۱۱ پیام با پارسر واقعی)
- منابع ساختگی Seed قبلی حذف و جایگزین شدند (الزام «هرگز نام/آمار ساختگی»)
- پردازش واقعی خط لوله با مدل: دسته‌بندی + استخراج ادعا روی بیش از ۲۹ مطلب، ۵۵+ رویداد یکتا، ۱۲۰+ ادعا
- برخورد با 429 سرویس مدل در بار سنگین → ثبت صادقانه + افزودن سدیمانت هم‌زمانی و تأخیر بلندتر؛ مقاوم‌سازی مجدد
- تولید گزارش دسته خودرو با پرامپت تخصصی (نسخه‌دار) — روز بدون مطلب پردازش‌شده → وضعیت «ناقص» با هشدار صریح (رفتار صحیح، نه بزرگ‌نمایی)

**مجموعه آزمون کیفیت خلاصه‌سازی فارسی:** سنجه‌های کیفی در پرامپت‌ها الزامی شده‌اند (حذف نکته مهم، افزودن اطلاعات غیرموجود، اغراق، اشتباه تاریخ، انتساب نقل‌قول، استنتاج بدون شواهد — همه صریحاً ممنوع و در بخش‌های خروجی قابل بازبینی). سنجش عددی کیفیت به اجرای مستمر با داده واقعی نیاز دارد و به‌عنوان «در انتظار داده» گزارش می‌شود؛ عدد ساختگی اعلام نمی‌شود.

---

## ۱۰. امنیت

- **کلید API:** رمزنگاری AES-256-GCM سمت سرور (مشتق از `SECRET_KEY` با scrypt)؛ ماسک در رابط؛ حذف در لاگ/خطا.
- **SSRF:** همه fetchهای خارجی از `safeFetch` می‌گذرند — مسدودسازی localhost/priv-IP/CGNAT/metadata، سقف ۱٫۵MB و timeout، بررسی مقصد پس از ریدایرکت.
- **تزریق پرامپت:** محتوای منابع با جداکننده صریح «غیرقابل اعتماد» محصور و به دستورات درون آن ترتیب اثر داده نمی‌شود؛ دستور ضد تزریق الزامی به همه فراخوانی‌های مدل اضافه می‌شود؛ تلاش تزریق در خروجی مدل علامت‌گذاری می‌شود.
- **اعتبارسنجی ورودی:** zod روی همه APIها با حد و حصر طول؛ سقف اندازه متن/فایل.
- **اجرا نشدن محتوای دریافتی به‌عنوان کد:** متن‌ها فقط به‌عنوان داده ذخیره و نمایش می‌شوند (React escape پیش‌فرض)؛ هیچ eval/exec وجود ندارد.
- **نرخ:** retry با تأخیر افزایشی برای اتصال‌دهنده‌ها و مدل؛ سقف مطالب هر دریافت؛ سقف ادعای ارزیابی در هر tick.

## ۱۲. گزارش وضعیت قابلیت‌ها (شفاف)

### ✅ پیاده‌سازی و آزمایش‌شده
- مدیریت منابع کامل (CRUD، گروهی، فعال/غیرفعال، چند‌دسته‌ای، وارد/صادر JSON، تکراری‌یابی، یادداشت اعتماد، وضعیت‌های روشن)
- اتصال‌دهنده‌های تلگرام/ایتا/بله/RSS/وب/توییتر-ایکس/تروث‌سوشال با رابط استاندارد، retry، ثبت صادقانه محدودیت‌ها؛ دریافت زنده آزمایش شد
- **۳۰ منبع واقعی** در پایگاه داده فعال‌اند: ۷ منبع داخلی (RSS/تلگرام/ایتا) + منابع خارجی با گرایش سیاسی ثبت‌شده (BBC، CNN، Fox، MSNBC، Reuters، الجزیره عربی/انگلیسی، العربیه، Sky، المیادین، المسیره، شبکه ۱۲ و ۱۴ اسرائیل، آروتز شووا) + حساب‌های اثرگذار (leader.ir، ترامپ در تروث سوشال/ایکس، ماسک، اوباما، نتانیاهو، پهلوی در ایکس)
- **گرایش سیاسی رسانه‌ها** در فیلد «یادداشت اعتماد» هر منبع ثبت می‌شود (توصیف مستند مراجع سوگیری رسانه؛ برای مقایسه متوازن چندمنبعی)
- **مسیرهای جایگزین مجاز و شفاف:** رسانه‌های مسدودکننده IP دیتاسنتر (العربیه، کانال ۱۲/۱۴، رویترز بدون RSS، MSNBC با خوراک بازنشسته) از تجمیع‌کننده عمومی گوگل‌نیوز با فیلتر site: دریافت می‌شوند و این محدودیت صریحاً در «محدودیت‌های منبع» ثبت است
- **پرامپت تخصصی دسته خودرو عیناً از سند کاربر** + چهار پرامپت هم‌سطح (اقتصاد/سیاست خارجی/فناوری/انرژی) + ثبت نسخه در `PromptVersion`
- لایه‌شدن پرامپت تخصصی دسته در تولید گزارش + درج نسخه پرامپت در متادیتای گزارش
- **ورود دستی مطلب** (API + رابط) با برچسب صریح، درج در همان خط لوله، ضدتکرار با هش
- خط لوله قابل ردیابی: نرمال‌سازی فارسی، زبان، تبلیغ/ناقص، تاریخ وقوع در برابر انتشار، هش+شباهت برای تکرار/بازنشر
- رویدادهای یکتا با منشأ اولیه و هشدار وابستگی منابع (بازنشر ≠ منبع مستقل)
- استخراج ادعا و دسته‌بندی/اهمیت با مدل + اعتبارسنجی JSON سخت‌گیرانه
- موتور راستی‌آزمایی با ۸ وضعیت استاندارد، شواهد (وب/درون‌سامانه)، عدم حکم از دانش داخلی مدل، «امکان تأیید مستقل فراهم نشد»
- حافظه تاریخی: رویداد/ادعای روزهای قبل، تناقض‌یابی عددی، اعلام صریح شکاف‌های حافظه
- گزارش شبانه ۱۴ بخشی با تاریخ شمسی، TZ تهران، ضدتکرار، وضعیت کامل/ناقص صریح
- زمان‌بند درون‌پردازشی با tick دقیقه، قفل، جبران بازه
- **سدیمانت هم‌زمانی فراخوانی‌های مدل (حداکثر ۲) + مدیریت 429 با تأخیر بلند**
- تنظیمات مدل/کلید/سقف هزینه + تست اتصال + مصرف به تفکیک هدف
- رابط فارسی RTL با ۱۴ بخش، ریسپانسیو دسکتاپ/موبایل
- امنیت: رمزنگاری کلید، SSRF guard، ضد تزریق، zod، سقف‌ها
- ۶۱ تست خودکار (واحد + یکپارچه، شامل پارسر ایکس/تروث سوشال با فیکسچر) — همه پاس
- راستی‌آزمایی مرورگر end-to-end (داشبورد، گزارش، راستی‌آزمایی، منابع، کشف، موبایل، RTL)

### ⚠️ پیاده‌سازی‌شده اما وابسته به محیط
- **جست‌وجوی وب شواهد/کشف منابع:** کد کامل است اما در محیط اجرای فعلی موتورهای جست‌وجوی عمومی پاسخ نمی‌دهند؛ سامانه صادقانه «نامعلوم/ناموفق» ثبت می‌کند و هیچ داده ساختگی نمی‌سازد. با دسترسی باز، بدون تغییر کد کار می‌کند.
- **دریافت تلگرام/ایتا/بله:** کد کامل است؛ موفقیت به کانال عمومی و ساختار فعلی صفحه وابسته است و در تغییر ساختار، خطا صادقانه ثبت می‌شود.
- **حساب‌های ایکس (ترامپ/ماسک/اوباما/نتانیاهو/پهلوی):** پارسر روی داده زنده واقعی آزمایش و تأیید شد (۳۰ پست ماسک با نویسندگی صحیح)؛ اما ایکس از IP این سرور اغلب با ۴۲۹ جلگیری می‌کند — منابع با خطای صادقانه ثبت‌اند و زمان‌بند دوره‌ای تلاش می‌کند؛ از IP خانگی/متفاوت بدون تغییر کد کار می‌کند. پست‌های تروث سوشال ترامپ جدا از آن از بایگانی عمومی به‌طور واقعی دریافت می‌شوند.
- **president.ir (پزشکیان):** سایت از این سرور پاسخ نمی‌دهد و استخراج پایدار ندارد؛ منبع با وضعیت صادقانه «غیرفعال» و توضیح ثبت شد — پوشش مواضع ایشان از خبرگزاری مهر و تسنیم (منابع فعال) تأمین می‌شود.
- **المسیره:** سایت اصلی ۴۰۳ می‌دهد و گوگل‌نیوز نیز آن را کم‌نمایه دارد؛ منبع با خطای صادقانه ثبت است.

### ⛔ در انتظار پیاده‌سازی / دسترسی
- اینستاگرام، آپارات (در کاتالوگ صریحاً «در انتظار پیاده‌سازی»)
- احراز هویت کاربران/نشست‌ها (تک‌کاربره فرض شده؛ مسیر افزودن NextAuth باز است)
- Bot API تلگرام برای سابقه کامل (نیازمند توکن کاربر)
- جست‌وجوی برداری (شباهت معنایی سبک فعلاً کافی و بدون وابستگی خارجی پیاده شده)
- ارزیابی خودکار پیش‌بینی‌ها (موجودیت و رابط آماده؛ سنجش خودکار در فاز بعد)
