# پرامپت حرفه‌ای اجرا — T9 + T10 (رصد‌بان)

> **روش کار:** این سند اول مطرح می‌شود، سپس گام‌به‌گام اجرا و در پایان تست و کنترل کیفی می‌شود.
> **اصل طلایی پروژه:** صداقت مطلق — هیچ داده ساختگی، هیچ موفقیت دروغین؛ هر خطا شفاف ثبت و نمایش داده می‌شود.

## صفر) عیب‌یابی خطای API ارزیابی — ✅ انجام شد

**شکایت کاربر:** کلیک روی «ارزیابی» هر خبر/کانال → خطای API.

**تشخیص با بازتولید واقعی (curl):**
```json
{"ok":false,"error":"همه مدل‌های زنجیره خطا دادند — zai: API request failed with status 429: Too many requests"}
```
**ریشه:** مدل اول GLM محدودیت نرخ ۴۲۹ گرفت؛ زنجیره انتقال خطا (failover) قبلاً ساخته شده بود
ولی همه تأمین‌کنندگان جایگزین به کلید API نیاز داشتند که تنظیم نشده → صفر جایگزین فعال → خطا مستقیم به کاربر.

## یک) T10 — زنجیره مدل‌های رایگان با انتقال خودکار خطا

**هدف:** اگر مدلی خطا داد (۴۲۹/تایم‌اوت/شبکه)، خودکار مدل بعدی امتحان شود.

**زنجیره نهایی (به ترتیب):**
1. `zai` — سرویس داخلی GLM (همیشه اول)
2. `pollinations` — **بدون کلید، همیشه فعال** — `https://text.pollinations.ai/openai` (تست واقعی شد: پاسخ فارسی سالم)
3. `fcc` — سرور محلی **free-claude-code** (github.com/Alishahryar1 — همان «FCC شاهریاری») در `127.0.0.1:8787/v1`؛ اگر کاربر اجرایش کند خودکار وارد زنجیره می‌شود، وگرنه صادقانه «غیرفعال»
4. `groq` / `openrouter` / `nvidia` / `github-models` / `together` — با کلید محیطی (`GROQ_API_KEY` و...)

**شبه‌کود:**
```
provider pollinations:
  kind: openai-compatible
  baseUrl: https://text.pollinations.ai/openai  → تمیزکاری URL تا .../chat/completions درست شود
  enabled: همیشه (بدون کلید)
  note: «رایگان بدون کلید — تأمین‌کننده جایگزین خودکار»
```
**پرهیز از خرابی:** مسیر فعلی `${base}/chat/completions` را با URL پایه pollinations سازگار کنیم (`baseUrl` شامل `/openai` تمام می‌شود → باید به `https://text.pollinations.ai/openai/chat/completions` برسد — درست است همان‌طور که هست).
**تست:** تست واحد زنجیره با تأمین‌کننده همیشه‌فعال + ارزیابی واقعی curl.

## دو) T9-الف — کانال خوانش‌شده → عضویت خودکار در فهرست منابع

**هدف:** هر کانالی که در «خوانش کانال‌ها» سنجاق می‌شود، خودش در فهرست منابع (Source) ثبت شود.

**شبه‌کود (در POST /api/channels پس از ساخت موفق WatchedChannel):**
```
upsert Source(platform=platform, identifier=normId):
  name = displayName || '@' + normId
  url = لینک کانال
  fetchMethod = 'خوانش کانال'
  status = 'دریافت_موفق'
  statusDetail = 'ثبت خودکار از خوانش کانال‌ها — N پیام اولیه'
  priority = 'عادی', isActive = true
```
- حذف کانال، منبع را حذف نمی‌کند (حفظ تاریخچه آرشیو).
- تست: افزودن کانال → فهرست منابع شامل همان شناسه.

## سه) T9-ب — دسته‌بندی موضوعی همه اخبار

**طبقه ثابت فارسی:** سیاسی، اقتصادی، نظامی-امنیتی، بین‌الملل، اجتماعی، فرهنگی-هنری، ورزشی، علم و فناوری، سلامت، محیط‌زیست، حوادث، سایر/نامشخص.

**شبه‌کود:**
```
POST /api/posts/categorize {limit=120, days=14}
  posts = پست‌های بدون دسته موضوعی (یا همه بازه)
  برای هر دسته ۳۰تایی:
    aiCall(طبقه‌بند) → JSON [{id, topic}]
    اعتبارسنجی topic ∈ طبقه‌ها؛ نامعتبر → «سایر/نامشخص»
    upsert PostCategory با Category خودکار (slug: auto-<topic>)
  پاسخ: {processed, categorized, errors[]}
GET /api/posts?topic=<slug> — فیلتر آرشیو
UI: پنل «تحلیل» → تب دسته‌بندی: شمارش هر موضوع + دکمه اجرا
```

## چهار) T9-پ — خوشه‌بندی اخبار مشابه + تایم‌لاین گره‌دار (اولین منبع → بازنشرها)

**مثال هدف کاربر:** بی‌بی‌سی ۹:۰۰ → CNN ۱۰:۰۰ → صداوسیما ۱۰:۳۰ — کاملاً مشخص چه‌کسی اول، چه‌کسی نقل کرده.

**مدل‌های تازه (Prisma):**
```
NewsCluster: id, title(خبر نماینده), firstPostId, firstSourceName, firstPublishedAt, memberCount, language, createdAt
ClusterMember: clusterId, postId(unique), isFirst, publishedAt, similarity, @@index(clusterId)
```

**الگوریتم خالص و تست‌پذیر (lib/clustering.ts):**
```
buildClusters(posts, {threshold=0.42, minSize=2}):
  برای هر جفت (پنجره زمانی ±48h):
    sim = jaccard(tokens(title+content))
    sim ≥ threshold → union-find ادغام
  خروجی: خوشه‌های ≥minSize با اعضا مرتب بر publishedAt
    first = قدیمی‌ترین → isFirst=true
    بقیه = بازنشر/بازگویی
```

**API و UI:**
```
POST /api/clusters/build {days=7, limit=800}
GET  /api/clusters?page=1  (با اعضا + منبع + زمان)
UI: پنل «تحلیل» → تب «خوشه‌ها و تایم‌لاین»:
  خط گره‌دار RTL — گره اول بزرگ/سبز با برچسب «اولین انتشار»،
  بقیه گره‌ها به ترتیب زمان با فاصله دقیقه‌ای و فلش «بازنشر»
```

## پنج) T9-ت — تحلیل رفرنس‌ها (ارجاع به واقعه تاریخی یا خبر دیگر) + راستی‌آزمایی

**مدل تازه:** `PostReference {id, postId, refKind(خبر_دیگر|واقعه_تاریخی|نقل_قول_مستقیم), refText, matchedPostId?, similarity?, verdict(مرتبط_و_معتبر|مرتبط_اما_تأییدنشده|بی‌ارتباط|یافت_نشده), analysis, model?, createdAt}`

**شبه‌کود:**
```
تشخیص نامزد: regex فارسی/انگلیسی —
  «به گزارش …»، «به نقل از …»، «بر اساس اعلام …»، «یادآور می‌شود …»،
  «در پی …»، «پس از …»، اشاره به تاریخ نسبی (هفته گذشته، دی ماه، ۷ اکتبر)
استخراج AI: JSON [{quote, refKind, description}]
راستی‌آزمایی هر رفرنس:
  جست‌وجوی درون‌پایگاه (jaccard بالاترین تطبیق با پست‌های دیگر)
  aiCall داوری: ارتباط متن ادعایی با رفرنس یافت‌شده/شواهد → verdict + analysis
  هیچ تطبیقی → صادقانه «یافت_نشده» (نه جعل)
API: POST /api/posts/[id]/references ، POST /api/references/scan {limit}
UI: تب «ارجاع‌ها» در پنل تحلیل + دکمه تحلیل در هر خبر
```
