# راهنمای راه‌اندازی رصدبان‌بات روی GitHub (رایگان)

ربات در `bot/bot.ts` کاملاً مستقل است (بدون دیتابیس و بدون وابستگی npm) و با GitHub Actions
**هر ۳۰ دقیقه** اخبار ۷۷ منبع را جمع می‌کند، ترجمه می‌کند و به کانال بله می‌فرستد.
روی ریپوی **عمومی**، دقیقه‌های Actions نامحدود و رایگان است.

---

## گام ۱ — ساخت ریپو و push

```bash
# در githhub.com یک ریپوی خالی «عمومی» بسازید (مثلاً raadban-bot) — عمومی = رایگان نامحدود
cd /home/z/my-project
git remote add origin https://github.com/<نام‌کاربری>/raadban.git
git push -u origin main
```

> ⚠️ **امنیت:** قبل از push، فایل‌های حساس از ردیابی خارج شده‌اند: `.env` و `db/` هرگز نباید
> در ریپو باشند (در .gitignore ثبت شده‌اند). توکن‌ها فقط در GitHub Secrets می‌روند.

## گام ۲ — افزودن Secrets

در ریپو: `Settings → Secrets and variables → Actions → New repository secret`

| نام Secret | الزامی | توضیح |
|---|---|---|
| `BALE_BOT_TOKEN` | ✅ | توکن بات بله (همان که در سامانه استفاده می‌شود) |
| `BALE_CHAT_ID` | ✅ | شناسهٔ عددی چت (مثلاً `1663835599`) |
| `OPENROUTER_API_KEY` | اختیاری | سرِ زنجیرهٔ مدل؛ سهمیهٔ رایگان ۵۰ درخواست/روز |
| `GEMINI_API_KEY` | اختیاری | پشتیبان دوم |
| `OPENROUTER_MODEL` | اختیاری | مدل رایگان دلخواه (پیش‌فرض `nvidia/nemotron-3-ultra-550b-a55b:free`) |

بدون هیچ کلید AI هم ربات کار می‌کند — Pollinations (بدون کلید) همیشه پشتیبان آخر است
و «GitHub Models» با توکن داخلی Actions خودکار در زنجیره هست.

## گام ۳ — فعال‌سازی و آزمون

1. تب **Actions** ریپو → اگر پیام «Workflows aren't being run…» بود، دکمهٔ سبز تأیید را بزنید.
2. روی workflow «رصدبان‌بات» → **Run workflow** → اجرا کنید (اجرای آزمایشی دستی).
3. لاگ را ببینید: `منابع قابل دریافت: 77` → `دریافت شد: …` → `خلاصهٔ چرخه`.
4. از این لحظه هر ~۳۰ دقیقه خودکار اجرا می‌شود.

## گام ۴ — جلوگیری از ارسال دوبارهٔ خبر

اگر گزارش نیم‌ساعتهٔ محلی سامانه (کانال بله درون‌برنامه‌ای) روشن بماند، همان خبر را
کانال محلی هم می‌فرستد. پس از اطمینان از کارکرد ربات گیت‌هاب، گزارش محلی را خاموش کنید:
**رابط سامانه → تنظیمات کانال بله → گزارش نیم‌ساعته: غیرفعال** (یا ناپرسیدن؛ فقط یکی فعال بماند).

## تنظیم‌های اختیاری (متغیر محیط در workflow)

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `NEWS_WINDOW_HOURS` | `3` | پنجرهٔ زمانی خبر (تحمل تأخیر کرون گیت‌هاب) |
| `MAX_ITEMS` | `12` | حداکثر خبر در هر چرخه |
| `BOT_MAX_SEARCH` | `2` | تعداد جست‌وجوی رایگان وب برای حکم ✅/⚠️ (۰ = خاموش) |

## افزودن/کم‌کردن منبع

منابع در `bot/sources.json`اند (صادره از دیتابیس سامانه). برای تغییر:
ردیف JSON اضافه/حذف کنید و کامیت بزنید — یا بعد از تغییر منابع در سامانه، محلی
`bun scripts/export-bot-sources.ts` را اجرا و `bot/sources.json` را کامیت کنید.

## رفع اشکال

- **«HTTP 403/ timeout» در همهٔ منابع:** IP اجراکننده محدود شده — لاگ Actions را ببینید؛ معمولاً گذرا است.
- **API بله از Actions پاسخ نداد:** اگر `getMe`/`sendMessage` از زیرساخت گیت‌هاب مسدود باشد،
  گزینه‌ها: (۱) اجرای همان `bun bot/bot.ts` روی یک سیستم همیشه‌روشن با cron نیم‌ساعته،
  (۲) Self-hosted runner، (۳) برگشت به گزارش محلی سامانه.
- **هیچ ایمیوجی ✅/⚠️ نمی‌بینم:** حکم فقط با شواهد جست‌وجوی وب داده می‌شود؛ بدون شواهد،
  عمداً هیچ حکمی نمی‌آید (اصل صراحت — هرگز حکم ساختگی نیست).
- **خبر تکراری دیدم:** حافظهٔ ضدتکرار در `bot/state.json` (۷۲ ساعت) است؛ اگر ریپو فورک/ریست شده،
  انتظار چند پیام تکراری در اولین چرخه‌ها طبیعی است.

## معماری در یک نگاه

```
کرون ۳۰ دقیقه (GitHub Actions، رایگان)
 └─ bun bot/bot.ts
     ├─ دریافت ۷۷ منبع (۷۵ RSS + ۲ تلگرام t.me/s) — همزمانی ۱۰، خطای هر منبع فقط در لاگ
     ├─ پنجرهٔ ۳ ساعت + حداقل کیفیت + ضدتکرار سه‌لایه (شناسه، عنوان نرمال، تجمیع ژاکارد)
     ├─ ترجمهٔ دسته‌جمعی غیرفارسی‌ها (یک فراخوانی سبک؛ بدون OpenRouter)
     ├─ تا ۲ جست‌وجوی رایگان Bing News RSS (شواهد حکم ✅/⚠️ — بدون کلید)
     ├─ یک فراخوانی مدل: انتخاب سیاسی + تجمیع + متن فارسی روان + حکم ایموجی‌ای
     │    زنجیره: OpenRouter → Gemini → GitHub Models → Pollinations (بدون کلید، همیشه)
     ├─ ارسال: هر رویداد = پیام «نام منبع: متن» (عکس خود خبر با کپشن، یا پیام متنی)
     │    شکست کامل مدل → مسیر خام صادقانه با سرصفحهٔ شفاف
     └─ ثبت bot/state.json و کامیت به ریپو (حافظهٔ ضدتکرار بین چرخه‌ها)
```
